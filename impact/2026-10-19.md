# Accomplishments: Week of October 19, 2026

## GitHub PRs & Reviews

- [PR #20009](https://github.com/hashicorp/vault-enterprise/pull/20009) (cont.): Added mount recovery so restoring a missing external plugin binary or registration and reloading can restore writes without restarting Vault; the PR is open.

- [PR #20093](https://github.com/hashicorp/vault-enterprise/pull/20093): Fixed the Database Overview page to list dynamic and static roles and generate credentials for either role type in Vault 2.2.0; the PR is open.

- [PR #3761](https://github.com/hashicorp/web-unified-docs/pull/3761): Consolidated three LDAP static-role rotation issues into the Vault 2.x known-issues guidance and recommended upgrading to 2.2.0; merged October 21.

- [PR #3772](https://github.com/hashicorp/web-unified-docs/pull/3772): Reviewed Oracle plugin 0.15.0 compatibility and release-note documentation, including an inline comment recommending a 1.21.12+ Enterprise requirement to avoid the known resource leak; merged October 22.

## JIRA

- [VAULT-51445](https://hashicorp.atlassian.net/browse/VAULT-51445) (cont.): Updated the investigation after further review: restoring the plugin binary or registration and running `vault plugin reload` can recover writes without restarting the node; tracked the fix in [PR #20009](https://github.com/hashicorp/vault-enterprise/pull/20009).

- [VAULT-51708](https://hashicorp.atlassian.net/browse/VAULT-51708): Took ownership of the related, reproduction-verified issue where `vault plugin deregister` can deregister a plugin that still has active mounts.

- [VAULT-51620](https://hashicorp.atlassian.net/browse/VAULT-51620): Created and closed a documentation task consolidating three LDAP static-role rotation issues and the 2.2.0 upgrade guidance in [PR #3761](https://github.com/hashicorp/web-unified-docs/pull/3761).

- [VAULT-51636](https://hashicorp.atlassian.net/browse/VAULT-51636): Explained how a blocked synchronous database static-role rotation can stall a mount’s queue, identified the missing timeout in the customer’s custom branch, and outlined stale-role removal or a 1.21.12 upgrade as recovery paths.

- [VAULT-48622](https://hashicorp.atlassian.net/browse/VAULT-48622): Clarified that the KV billing walk can cause memory spikes and OOMs on smaller environments even when a test shows no unbounded growth or OOM.

- [VAULT-51668](https://hashicorp.atlassian.net/browse/VAULT-51668): Triaged the eMudhra intermediate-CA compromise, set high customer severity, routed the issue to CryptoSec, and linked the emergency-release work.

- [VAULT-51712](https://hashicorp.atlassian.net/browse/VAULT-51712) and [VAULT-51731](https://hashicorp.atlassian.net/browse/VAULT-51731): Reproduced the Vault 2.2.0 Database Overview credential-display failure, attached before/after evidence, opened [PR #20093](https://github.com/hashicorp/vault-enterprise/pull/20093), and closed the duplicate report.

## Summary

- Work spanned Vault’s database secrets engine—from Oracle plugin compatibility and static-role rotation to a Vault 2.2.0 credentials flow in the Database Overview UI. It also covered external-plugin recovery and deregistration, LDAP rotation guidance, database rotation-queue behavior, KV billing memory pressure, and security triage. I paired those investigations with Enterprise fixes, customer-facing documentation, and a safer local Raft development sandbox workflow.
