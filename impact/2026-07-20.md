# Accomplishments: Week of July 20, 2026

## Accomplishments

### Vault Enterprise PR's

- [PR #16674](https://github.com/hashicorp/vault-enterprise/pull/16674): Fix Windows file audit-device enablement for drive-letter paths and `plugin_directory`, including expanded external tests.

- [PR #16619](https://github.com/hashicorp/vault-enterprise/pull/16619) (cont.): Preserve query parameters across double-slash redirects; the PR was merged during the week after additional external tests were added.

### JIRA

- [VAULT-41268](https://hashicorp.atlassian.net/browse/VAULT-41268): Windows audit-device enablement regression involving drive-letter paths and `plugin_directory`. Confirmed the fix and backports after moving the issue through triage and investigation.

- [VAULT-47462](https://hashicorp.atlassian.net/browse/VAULT-47462) (cont.): Double-slash redirects dropped list-operation query parameters. Reproduced the issue, added tests, and confirmed the main-branch fix and backports.

- [VAULT-46830](https://hashicorp.atlassian.net/browse/VAULT-46830): Prometheus startup panic caused by a negative counter value. Documented the `armon/go-metrics` root cause and attached an RCA.

### Vault Reproductions Improvements

- Added the [Prometheus Negative Counter Panic KB](../telemetry/prometheus-negative-counter-panic-kb.md) for [VAULT-46830](https://hashicorp.atlassian.net/browse/VAULT-46830), including the exact panic, dependency call chain, a self-contained reproduction, candidate negative-counter call sites, and the guarded-sink fix. The catalog entry was added in commit [`28dfd7a`](https://github.com/nicholasfrei/vault-reproductions/commit/28dfd7a0d8b742799911e4962d82b6025c111721), after the KB was authored and refined in [`7e39f49`](https://github.com/nicholasfrei/vault-reproductions/commit/7e39f49adad4e3bb8069d452906c743ba46b1bba) and [`2bd323a`](https://github.com/nicholasfrei/vault-reproductions/commit/2bd323ac279b86b85be59204360bf269f186a9).

- Added the [Snowflake database role partial-update reproduction](../secrets/database/snowflake-db/vault-db-role-update-partial-payload-repro.md) and its AWS/Terraform lab under `secrets/database/snowflake-db/terraform/`. The reproduction documents how Terraform Vault Provider versions 5.8.0–5.10.1 can send partial update payloads that cause unchanged database-role fields to reset on Vault 2.0.x; see upstream [terraform-provider-vault#2966](https://github.com/hashicorp/terraform-provider-vault/issues/2966) and commit [`9a6bfbc`](https://github.com/nicholasfrei/vault-reproductions/commit/9a6bfbc2594fd5f256254729ed18184af7c1c29).

### Summary 

- This week touched Vault HTTP redirect and CLI request-path handling, Windows audit-device and plugin-directory behavior, and Prometheus telemetry safety across the `armon/go-metrics` and `prometheus/client_golang` layers. I also investigated database secrets-engine role updates with the Terraform provider and Snowflake, converting the findings into reproducible documentation.
